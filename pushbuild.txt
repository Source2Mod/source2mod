First Source2Mod release: Source2Toolkit renamed and carried on, with SourcePawn plugins (.smx) next to native ones on one API, plugin API 5.
Crash reports name the SourcePawn plugin and function (and dumps carry the plugin block, as Accelerator's do); SourcePawn hot reload on Windows too, debounced on both platforms; GeoLite2 City + Country shipped in shared/; source2mod.net.
Blocked game events are freed after every plugin's FireEvent hook has run (fixes a crash in MultiAddonManager and other FireEvent hooks); CTakeDamageInfo.m_iHitGroupId natives removed.
Drop transmit bits outside the pack unions after CheckTransmit. #2
Menu-key fakes are no longer announced as dormant to players who never received them (everyone could lose the connection while one player spammed a menu); a menu reopened during the fake handover finishes it first.
Runs side by side with CounterStrikeSharp (one free per blocked game event; "/" hides only Source2Mod's own commands); PlayerChat hook point on Host_Say and the player_chat game event, once per chat line; HookConCommand / UnhookConCommand replace RegisterConListener -- plugin API 6, plugins built against 5 need a rebuild; resolved addresses kept; SendNetMessage hooked only while something listens.
After CheckTransmit, the out-of-PVS and dont-transmit sets also hold only entities that get packed. Entities missing from the engine's networkable list are dropped from the transmit set too. This fixes the FATAL ERROR "WriteEnterPVS: GetEntServerClass failed".
Menu-key fakes are no longer deleted by the game: the unowned-weapon cleanup (mp_death_drop_gun 0) and the round restart map cleanup left them out of the snapshot while their handle still went into m_hMyWeapons, the cause of the FATAL "WriteEnterPVS: GetEntServerClass failed".
Chat: a "/" line for a command that is not Source2Mod's no longer shows in chat (it still goes on as an ordinary say, so say listeners and CounterStrikeSharp's "/x" commands see it; only Host_Say is skipped); "!" lines reach the say listeners too. GetItemInLoadout hook point. SourcePawn natives split along core/.
CS2 1.41.9.2: built against the fixed IVEngineServer2 (new virtual at slot 65 shifted every engine call from SynchronouslySpawnGroup on), new signatures for CCSPlayerPawn::PostThink, CDecoyProjectile::EmitGrenade, CSmokeGrenadeProjectile::EmitGrenade and GetWeaponCSDataFromKey, schema regenerated. A plugin loaded late (s2m load, refresh, hot reload) now gets OnAllSource2ModPluginsLoaded / OnAllMetamodPluginsLoaded.
SDK: CTakeDamageInfo / CTakeDamageResult on the schema (the result was 16 bytes short and 12 bytes off after m_flPreModifiedDamage), CTakeDamageResult(CTakeDamageInfo*), Schema* class ops, the game's trace filters (tracefilter.h, CTraceFilterSimple replaces CTraceFilterEx), s2sdk's CRecipientFilter and CGlobalSymbol, s2sdk cb545fbe; core: plugin-metadata.json, entity system and global vars read fresh, SourcePawn view_as<float>(call()) fix, unload safety after failed loads, NetworkStateChanged slot scan limited to 16 bytes.
ISource2ModConfigs001: plugin configs declared once with their defaults (example written, missing file created, merged over the defaults, reloaded on change, "s2m config"); core.json, permissions.json and databases.json on it. core.json gains ConfigHotReloadEnabled.
SourcePawn plugins get configs too (source2mod/configs.inc, Source2ModConfig.Register). "s2m load <name>" loads the plugin named exactly that before a partial match; several partial matches are reported instead of loading the first.
Config defaults can be built key by key: Source2ModConfigDefaults (C++ header-only, and the SourcePawn methodmap of the same name), comments included in the generated files.
On s2sdk 121697ac (ClientPutInServer hook on ClientPutInServerType_t); SourcePawn bump with int64 <-> double view_as on rvalues; metadata url www.source2mod.net.
SDK headers moved to source2mod/sdk/ (schemasystem_helper.h, sdk/schema/classes|enums, sdk/game/shared|server, sdk/navlib); SourcePawn schema methodmaps one file per class and enum (source2mod/sdk/schema/...), still pulled in by <source2mod/schema>. Plugins built against the old include paths keep loading; source changes only.
ISource2ModClients002: everything answered off the engine client (CServerSideClient), not the controller; GetServerSideClient, QueryClientConVar (SVC_GetCvarValue, CANCELLED on disconnect) and the per-client helpers moved off the controllers (ReplicateConVar, GetIpAddress, PrintTo*, PrintToCenterHtml, ExecuteClientCommand(FromServer), FireEventToClient, Disconnect replacing Kick); SourcePawn methodmap CServerSideClient. Slot loops and checks bounded by maxClients instead of 64, SourcePawn MaxClients follows it. Plugins that ask for ISource2ModClients001 need a rebuild.
Older interface revisions served through generated compat adapters (src/compat, tools/ifacecompat): from the next interface change on, plugins built against the previous revision keep loading. No interface changed in this release.
Per-client calls also on the interfaces you look for them on first: ISource2ModCommands005 (ExecuteClientCommand, ExecuteClientCommandFromServer), ISource2ModConVars004 (QueryClientConVar, ReplicateConVar), ISource2ModEvents003 (FireEventToClient), and the same as Source2ModCommands / Source2ModConVars / Source2ModEvents natives. Plugins built against Commands004, ConVars003 and Events002 keep loading through compat adapters.
HTTP falls back to the core's own client (Boost.Beast) where Steam's cannot take a request (core.json HttpFallback), ISource2ModWebSockets001 and the Source2ModWebSocket natives, breakpad built from source, OpenSSL/MySQL/Boost kept out of the export table, FP_VPROF, one author string everywhere.
Windows: the net library builds with /bigobj (the previous release failed there with C1128).
Plugins served through a compat adapter no longer log it: it works and says nothing.
Plugin API 8, every plugin must be rebuilt: each plugin gets its own interface instances, no call takes a plugin id or reads a code address any more. New ISource2ModModules app system owns the modules (LoadModule/FreeModule removed), ISource2ModFunctions takes ISource2ModModule*, HookTarget::Class looks in the common modules or a named one, gamedata "function" objects can name a vtable. Older compat adapters removed.
Windows: the crash listeners build again (the previous release failed there with C2084).
Windows: Source2ModModule builds again (windows.h renamed GetModuleHandle, the previous attempt failed with C3668).
New: ISource2ModVoice (voice flags and listen overrides per plugin, combined by the core), ISource2ModFunctions::FromDatamap, core.json FollowCS2ServerGuidelines (default true, servers that set inventory or Valve DS fields need false).
SourcePawn plugins have their plugin id again (plugin API 8 lost it): their hooks are removed when they unload or fail to load, which fixes a crash in a ConVar change hook, and Source2ModConfig.Register works.
SourcePawn catches up with C++ and the engine: net channel stats and client state on CServerSideClient; launch parameters, address, build, hibernation, performance, demo, timescale and console output (AddConsoleListener, ServerCommandEx) on Source2ModEngine; ConVar and command lists; CUserCmd in RunCommand and SetupMove; bans and fake clients; SendMessageDirect; Source2ModMenuInstance for own menus; a config validator; NetworkStringTable, Source2ModSpawnGroups, mounted addons; Source2ModMemoryBlock, Source2ModPatch, FromPointer; CUtlVector counts and more enums in the schema. Protobuf accessors no longer die on a field of another type.
Plugin API 9: ISource2ModAPI in order, with every subsystem on it (Clients, Configs, Files, Functions, Hooks, Voice, ...). Plugins built against 8 keep loading, the core hands them the old layout.
Custom HUD classes and strings go through the game's own state setters (two new gamedata signatures, the old write stays as a fallback), for HUD menus that show their rows without any text.
Plugin API 10: ISource2ModAddresses, ADDR_* and the SourcePawn addresses are gone, game functions are found by gamedata name through ISource2ModFunctions. Plugins built against an older API are refused, every plugin has to be rebuilt.
Menu-key fake weapons can only be acquired by the player whose menu made them, and a plugin hiding a pawn with its weapons no longer marks that player's fakes dormant for other viewers.
SourcePawn: CenterHtmlMenu.SetCooldownHandlers, a script's own cooldown handlers for AddMenuOptionWithCooldown.
The mouse wheel switches real weapons while a menu takes keys, instead of doing nothing in it. ISource2ModMenus.SetKeyWeapons (SourcePawn too) turns a player's menu-key fake weapons off.
ISource2ModEntities.SpawnEntityByClassname (SourcePawn too): creates and spawns an entity in one step with its resources precached, also a weapon nothing has precached. cs_script and custom HUD layouts spawn through it. s2sdk up to date with upstream.
ISource2ModEntities.CreateEntityKeyValues: spawn keyvalues from the game's allocator with classname, origin and angles. SourcePawn's SpawnEntityByClassname takes origin and angles.
s2m hookdebug slotinput logs who removes a menu-key fake, with the stack.
The server log says how many plugins loaded at startup.
Plugins built against older interface revisions load again: ISource2ModMenus008 and ISource2ModEntities004 are served through compat adapters, each plugin through its own instance. Commands004, ConVars003 and Events002 are back too.
Slotinput: the menu-key fakes leave the weapon list before the game frame's post handlers, so weapons given from menus (mode guns, shop grenades) and pickups no longer find their slot taken. hookdebug slotinput skips the core's own removals and keeps the stack short.
s2m hookdebug slotinput logs every menu key press: what the weaponselect picked (which fake or which real weapon) and what slotinput did with it.
Slotinput: the menu-key fakes leave the weapon list at every CanAcquire, so no give, pickup or purchase finds its slot taken by one; hookdebug slotinput also logs real weapons removed from a player with a menu open.
Slotinput: plugins (C++ and SourcePawn) never meet the menu fakes -- hook points, game events, entity listeners and menu key delivery skip them and see m_hMyWeapons without them; the list is swept of fakes and dead handles on every Eject (a shop grenade no longer lands on the floor).
Game events: hooks on round_poststart, item_equip, bomb_*, round_mvp and most other events fire again -- the core adds its listener back after each .gameevents file, which defined the events anew without it, and the game does not create an event nobody listens to. ISource2ModEvents004 (and SourcePawn's Source2ModEvents) reads the event table: GetEventCount, GetEventName, GetEventID, GetEventListenerCount, IsClientListening, GetEventFile, IsEventLocal, IsEventReliable.

New hook point HookPoint::ClientFullyConnect.

Plugin API 11: ISource2ModAPI hands out the resource system, manifest registry, resource handle utils, flattened serializers, serialized entities, game types, script manager, async file system and process utils (SOURCE2MOD_FILLGAMEVARS fills s2sdk's globals); built against s2sdk cs2 21654ee5.
